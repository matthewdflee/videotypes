# 工程规范

风格文档回答"长什么样、怎么实现"，本页回答"这个 skill 凭什么能稳定复现"。内容沉淀自外部参考视频对 Remotion 视频生成 skill 的工程要求，并已对齐随附 Remotion 工程的实际结构。**没有落实的条目会明确标注为「待落地」**，不把设计说成现状。

## 一、工程底座与代码规范

### 已落地

- **统一技术栈**：Remotion 4 + React 19 + TypeScript，`package.json` 固定版本（`^4.0.534`），Node 22.18+。
- **固定目录结构**：
  - `src/kit/`：共享内核（相机 `camera.tsx`、着色器 `gl.tsx`、字体 `fonts.ts`、文本 `text.tsx`、时间 `time.ts`、声音 `vo.ts`、核心组件 `core.tsx`）。
  - `src/styles/<id>/`：各风格组件包，19 套内置风格一一对应。
  - `projects/<片名>/`：每部新片一个目录，`Main.tsx` 导出 `Main` 和以秒为单位的 `DURATION`。
  - `references/`：风格文档、工具选择、制作验收、提示词库。
- **标准化接口**：新片统一用 `Main.tsx` + `vo.json` + `beats.json` + `post.json` 四件套，命令走 `scripts/render.mjs`（见 [制作与验收](制作与验收.md)）。
- **确定性铁律**：动画由当前帧号/`useT()` 驱动，禁止 `Math.random()`、实时时钟和 CSS transition 驱动画面。随机必须用固定 seed。这条写死在每个风格文档的「坑」节里。
- **函数组件 + Hooks**，无类组件。

### 待落地

- 风格组件的统一 props 契约（`content` / `duration` / `themeConfig`）。当前 19 套组件接口不完全一致，新风格按此契约写，旧的逐步对齐。

## 二、视觉系统

每个风格文档已经固化的部分：

- **色彩体系**：色值表（背景/主/辅/文字/强调），像素风额外固定调色板。
- **字体规范**：标题、正文、字幕各用什么字体和字重；开源可商用字体已打包在 `fonts/`（含 OFL 许可证，见 `fonts/licenses/`）。
- **动效预设**：入场/退场类型、时长、缓动；每套风格有 2–3 种专属转场。
- **布局网格**：安全边距与三区布局；`linev`（风格 34）已定义 9:16 竖屏安全区，其余风格默认 16:9。

**尚未全局固化**：统一的布局网格变量（目前散在各风格文档里）。做竖屏片时按风格 34 的安全区定义取。

## 三、音频系统

### 已落地

- `scripts/silent.py`：从 `vo.json` 生成 `vo.timing.json`（无配音模式）。
- `scripts/voice.py` + `edge-tts`：配音模式（需联网，需在 `.venv` 装 `edge-tts`）。
- `scripts/sound.py` / `scripts/sfx_voice.py`：可复现的声音编排与合成，输入 `sound.json`。
- `scripts/audiocheck.py`：抽 BPM、峰值、响度（pyloudnorm），用于节拍对齐和音量检查。

### 约定

- 默认交付**无 BGM、无配音**，字幕叙事，音效只配关键节点。这是 SKILL.md 的默认值，不要主动加铺乐。
- 无配乐模式下 `sound.json.music` 可为空，或仅含 `air` 环境底噪（脚本把底噪归在这个总线）。
- 稀疏音效不强行拉到 -14 LUFS，不为凑响度抬高底噪。
- 每个风格文档的「声音」节是该风格的音效映射表，制作时落成 `sound.json`。

### 待落地

- 免版权 BGM 素材库与自动匹配（按风格绑定曲风/BPM 标签）。当前**不内置任何音乐文件**。

## 四、内容结构与叙事模板

### 已落地

- **先时间轴后画面**：`vo.json` → `vo.timing.json`；多镜头共用的关键时刻进 `beats.json`，用 `T('a1')`、`T('a1.end')`、`T('a1@关键词')` 驱动画面、读数与音效。**同一个剧情锚点只在一个文件里写一次。**
- **镜头表**：`brief.md` 里写"发生什么 → 状态如何改变 → 观众因此理解什么"。
- **字幕规则**：1080p 下宋体/黑体 50px、像素字 48px、得意黑对话 52px；单行约 26 字以内，优先拆句不缩字；竖屏字幕按风格 34 的底部区。

### 待落地

- **分镜自动拆解**：按输入文案的字数/段落数自动分镜头、分配时长。目前靠 `brief.md` 手工拆，`silent.py` 只做阅读速度估算。
- **素材适配**：用户插入图片/图表后自动套风格的蒙版、滤镜、边框。目前需在项目里手工处理。
- 抖音流量结构模板（钩子开场 → 核心内容 → 总结引导）：SKILL.md 已要求前 3 秒出现具体事件和钩子句，但未固化成可配置的模板。

## 五、模型兼容与容错

不同模型的能力差别很大，同一套提示词不能一刀切。做片时按当前模型的强度选一档：

### 三档提示词体系

| 档位 | 适用模型 | 做法 |
|---|---|---|
| **完整版** | 强模型（能一次生成完整可运行工程） | 直接给风格文档 + 提示词 + 参考示例路径，让它生成 `Main.tsx` |
| **分步版** | 中等模型 | 拆成三步，每步单独确认：① 读风格文档写 `brief.md`（镜头表 + 母题）→ ② 写 `vo.json` + `beats.json` 定时间轴 → ③ 生成 `Main.tsx` |
| **降级版** | 低算力/易出错模型 | 先让它生成静帧构图（1–3 个代表帧），确认视觉语言后再加动画；动画从"位移 + 淡入"起步，逐步加弹跳和转场 |

### 错误处理

- `node scripts/check.mjs --proj <片名>` 做类型检查，生成项目专用临时配置，逐个查 `@proj` 引用。
- 渲染失败时先看 `scripts/render.mjs` 的报错；静帧失败先降复杂度（关 bloom、降分辨率）再重试，不要把问题攒到最后。
- **渲染未完成不宣称交付**。工具返回"仍在运行"就继续等；预算暂停就重跑同一命令续渲（`--budget` 是软预算）。
- 失败时报告原因、已完成文件和续跑命令，**不把脚本当成成片**。

### 分步确认

支持"先生成分镜 → 用户确认 → 生成代码"。用户说"把第二个镜头的文字改大一点"时，定位到对应 `<Series.Sequence>` 局部改，不要重新生成全片。

## 六、交付与使用体验

### 已落地

- **风格选择器**：本页开头的 34 行索引表 + `references/风格库.md`，按 ID 或中文名选。
- **参数配置**：分辨率/帧率/时长/是否配音，默认值写在 SKILL.md 与各风格文档。
- **输出标准化**：`projects/<片名>/` 归档；`render.mjs` 产出 `<P>.mp4`；旧静帧和缓存保留。
- **文档与示例**：19 套内置风格有可运行示例；15 套新风格有规格文档和提示词，**尚无随附示例工程**（见风格库的状态列）。

### 待落地

- 自动按「日期-主题-风格」命名归档。
- 自动生成抖音发布用的文案与标签建议。
- 15 套新风格的 Remotion 示例工程——按实际做片情况逐个沉淀，先做静帧构图，验证后再补示例入口，不伪造 TSX 文件。
